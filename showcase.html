Simple Material

Material 3 styling for plain, semantic HTML. No classes, no divs and no JavaScript: link one stylesheet and write ordinary markup.

The menu at the top of the navigation picks a colour theme. In the top bar, a segmented button made of three radios named color-scheme switches between light and dark; Auto follows your system setting. On a narrow screen the navigation folds into the ☰ menu.

Colour themes

Every colour is derived from a hue, so a theme is a few settings that work in light and dark mode. Violet is the default, and rose, orange, olive, teal and navy start from popular Coolors palettes. Pick one with data-theme on the html element: 

<html lang="en" data-theme="teal">

A select named theme, like the one at the top of the navigation, switches between them without JavaScript.

To make your own, set the four values a theme sets on :root: 

:root {
  --hue: 150; /* primary hue, in degrees */
  --tertiary-hue: 30; /* accent hue, used by mark */
  --chroma: 0.8; /* how colourful the accents are */
  --tint: 1.5; /* how strongly the hue tints surfaces */
}

Buttons

A button is filled by default; data-variant selects the other Material styles. A link with a data-variant looks like a button but keeps its link role. Press one to see the ripple.

Link as button 

<button>Filled</button>
<button data-variant="outlined">Outlined</button>
<button data-variant="icon" aria-label="Settings">⚙</button>
<a href="/docs" data-variant="tonal">Read the docs</a>

Badges & tooltips

Put data-badge on a sup for a count, or leave it empty for a dot. Add data-tooltip to show a plain tooltip on hover and keyboard focus. On icon buttons, repeat the text in aria-label.

Hover or focus me 

<button>Inbox <sup data-badge>12</sup></button>
<button data-variant="icon" aria-label="Help" data-tooltip="Help">?</button>

Cards

Every article is a card. Put several in a data-layout="grid" container to lay them out in columns. An image placed first runs to the edges. data-variant="filled" and "outlined" give quieter cards.

Layout & grouping

Add data-layout to any container to place its children side by side: "grid" gives equal columns, "row" keeps natural widths and "split" gives a wide and a narrow column. Each falls back to a single column when space runs out. A section inside another section is a card, so it can group anything.

Text fields

Wrap each control in its label, so no ids are needed. Fields use the filled Material style and the focus line grows from the centre. Errors appear only after someone has interacted with a field (:user-invalid). A fieldset arranges its fields in responsive columns.

Selection controls

Checkboxes, radio buttons and switches are native inputs inside their label. A switch is a checkbox with role="switch". A range is a slider whose bar handle narrows while dragged.

Chips

A fieldset data-variant="chips" turns its checkboxes or radios into filter chips; a tick slides in when one is selected. A single button data-variant="chip" is an assist chip.

Progress & meters

A progress with a value is determinate; without one it animates. data-variant="circular" makes a spinner. A meter changes colour based on its low, high and optimum values.

Navigation

The top app bar is body > header and the side navigation is body > nav. Give the side nav the popover attribute and put a button with popovertarget first in the app bar: on narrow screens the nav becomes a drawer behind that button, and it closes on Esc or a tap outside. Inside the content, a nav holding an ol is a breadcrumb trail, and one holding a ul is a row of links such as pagination. Mark the current item with aria-current. 

<header>
  <button popovertarget="menu" data-variant="icon" aria-label="Open menu">☰</button>
  <a href="/">Site name</a>
</header>
<nav popover id="menu"><ul>…</ul></nav>

Tabs

Tabs are details elements that share a name, inside a data-variant="tabs" container. Opening one closes the others. Browsers without ::details-content show them as an accordion instead.

Expansion panels

Each details is a panel that animates open and closed. Panels that share a name behave as an accordion.

Do I need JavaScript?

No. Every widget on this page works with HTML and CSS alone.

Can I change the colours?

Pick a theme with data-theme on the html element, or set --hue on :root. Every colour role is derived from it, in both light and dark mode.

Which browsers are supported?

Current Chrome, Edge, Firefox and Safari. Features a browser lacks degrade to simpler, still working widgets.

Dialogs & sheets

A dialog opens with commandfor and command="show-modal", so no script is needed. Buttons in a form method="dialog" close it, as does Esc. data-variant="sheet" docks the dialog to the bottom of the screen.

    Snackbar

    An output with popover="manual" becomes a snackbar that slides up from the bottom. Buttons inside it close it with popovertargetaction="hide".
